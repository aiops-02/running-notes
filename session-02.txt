Relabel configs
================
prometheus treats targets as set of labels. Prometheus can do a list of edits before scraping the targets. 

up{instance="mysql"}

1. identify the targets
2. scrape the metrics
3. store the metrics
4. alerts

service discovery will give some metadata labels along with targets. prometheus can use those labels or drop them

a label start __ is a scrape setting, prometheus uses it to build the metric then it throws away..

a label does not start with __ goes into metrics


- job_name: "node"
    ec2_sd_configs:
      - region: us-east-1
        port: 9100
        filters:
          - name: tag:Monitoring
            values: ["true"]
    relabel_configs:
      # no keep rule: every Monitoring=true instance is a node target
      # --- labels on every series (instance stays <private-ip>:9100) ---
      - source_labels: [__meta_ec2_tag_Tier]
        target_label: tier
      - source_labels: [__meta_ec2_tag_Component]
        target_label: component
      - source_labels: [__meta_ec2_tag_Project]
        target_label: project
      - source_labels: [__meta_ec2_tag_Environment]
        target_label: env
      - source_labels: [__meta_ec2_tag_Name]
        target_label: name
      - source_labels: [__meta_ec2_instance_id]
        target_label: instance_id
      - source_labels: [__meta_ec2_availability_zone]
        target_label: az

white box monitoring and black box monitoring
=============================================
white box monitoring -> we know about sytem internals.
black box monitoring -> not knowing about system internals. but we know something like website is working or not. DNS is resolving or not. certificate details. how much time it is taking to respond.
